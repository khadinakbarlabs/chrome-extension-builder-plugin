# Support

Provide plugin version, host/version, relevant skill or local command, and a minimal sanitized reproduction with expected/observed behavior. State whether the issue concerns chat planning, optional Studio, local files/tooling, a generated extension, a backend, or store preparation.

For actual browser failures, include browser/version, build identity, surface/action, and redacted error code. Use a synthetic page/account. Do not send credentials, cookies/tokens, OTP, card data, PHI, government IDs, customer records, profiles, transcripts, or unredacted production logs. Avoid private URLs and secret-bearing source lines.

If tools or local access are absent, the conversational workflow can still produce briefs, architecture, UI specifications, code, and tests in normal Markdown. Missing runtime proof should be listed as unrun, not a pass. Studio is optional and manually started; installation does not start services or connect accounts.

No public support URL or dedicated contact is configured in this package. A reachable published support contact, along with homepage/privacy/terms links, must be verified before a public directory listing. Do not invent an address or send reports to an unrelated service.
