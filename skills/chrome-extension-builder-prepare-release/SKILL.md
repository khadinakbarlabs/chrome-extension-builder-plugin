# Chrome Extension Builder: Prepare Release

Before starting, read [policy boundaries](../chrome-extension-builder/references/policy-boundaries.md). No credentials/restricted-data intake, digital plugin upsells, or inferred publication authority.

Route to [chrome-extension-builder-release](../chrome-extension-builder-release/SKILL.md), selecting security/browser QA where necessary. Prepare a concrete package/checklist or chat-ready release specification before asking for missing material authority. Check explicit environment capability before executing tools. Preserve user authorization; no magic token gate.

Exit with exact artifacts, observed checks, remaining cases, and actual distribution status. A local ZIP, submitted item, accepted store version, and deployed backend are separate outcomes. Do not claim portal acceptance or live billing from preparation.

## Context and outcome handoff

Use compact context and exact release target. Recheck affected stale gates, route to release work, and show a [dated outcome](../chrome-extension-builder-report/SKILL.md); preparation is not external submission authority. Preserve the canonical report destination assigned by `references/team.json`; any overview is a dated view, not a competing authority.
