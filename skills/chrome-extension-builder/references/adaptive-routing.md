# Adaptive routing

Select the smallest complete path resolving the user's objective. A route is a recommendation, not proof a specialist ran. Read `team.json` only for relevant roles/canonical reports. Use supported authorized delegation with disjoint ownership; otherwise label distinct sequential passes.

| Intent | First useful work | Follow-through |
| --- | --- | --- |
| New build | Research material unknowns; architecture/UX define acceptance | Implement useful slice, relevant security/runtime QA/performance, delivery |
| Improve | Inspect current journey and evidenced pain; retain accepted direction | Measured alternatives when useful; targeted regression and visual evidence |
| Fix | Current artifact and failing reproduction; affected trust/context boundary | Minimal repair, regression, relevant security review; avoid research restart |
| Audit | Scope evidence against exact artifact | Findings, impact, missing proof; repairs only within requested scope |
| Prepare release | Artifact identity and freshness | Resolve relevant QA/privacy/security/package gates; prepare concrete assets; no inferred publishing |
| Continue | Compact authorized recap, reconcile changed facts | Resume earliest unsatisfied dependency; don't repeat completed verified phases |
| Feedback | Distinguish builder from generated product and reported from observed | Reproduce/prioritize, targeted repair/evaluation |
| Requested follow-up | Capability, intent, source scope | Supported host activation and actual evidence; no plugin daemon |

Architecture/UX establish interfaces before frontend/backend/integration parallel work. Security begins at design and reviews final boundaries. Runtime QA needs a relevant built artifact; performance needs comparable measurements. Release cannot skip unresolved critical gates. Debugging rejoins affected checks, not necessarily the entire lifecycle.

A changed requirement identifies impacted contexts/permissions/interfaces/UI/tests/evidence; mark affected evidence stale and run the smallest meaningful checks. Mark irrelevant stages not applicable with reasons. Skipped work is not a pass. Review hypotheses before adding accounts/backend/analytics/dependencies.

Capability, authorization, and proof are independent. Browser capability does not authorize private-page collection. A schedule spec is not activation. Screenshots don't prove worker recovery. Declared agents don't prove independent evaluation.

Use [engineering defaults](engineering-instincts.md) and [recipes](task-recipes.md) when they fit. End useful milestones with [outcomes](reporting-and-visual-evidence.md): result, evidence, limits, next dependency. Optional feedback is not a continuation gate.
